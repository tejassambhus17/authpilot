# AuthPilot design system

## Direction
An integration field guide inside a precise developer workspace. The product is used beside a code editor; navigation stays quiet, reading stays generous, and evidence is part of the workflow. The user approved this workspace direction. Operate mode for the directory/research, Read mode for guides.

## Tokens
Self-hosted DM Sans Variable; body 14px, reading 15px/1.75, page title 36–46px, headings tracking -0.035em. Light canvas #fafbf8, white surfaces, foreground #1c2923, muted #627068, borders #e3e8e0. Brand forest #245c45, accent wash #edf3e9, amber evidence #83561a. Dark canvas #141a17, surfaces #1b231e, foreground #e8eee8, muted #a6b3a9, borders #303b33, brand #a8d9b7. Spacing 4/8/12/16/24/32/48/64px. Controls 8px radius, panels 14px. Elevation reserved for menus.

## Layout and interaction
232px sidebar on desktop; mobile sheet navigation. Max content 1200px. Directory uses a scan-friendly provider table. Research has an actual event journal. Guides use semantic tabs with arrow keys, source references and a local progress rail. Accent appears on useful actions and verified evidence, never as decoration. Icons from Lucide, consistent 1.7px strokes. Custom AuthPilot mark is exact vector geometry.

## Accessibility
Visible 3px focus rings; accessible form labels; no color-only status; minimum 44px primary control targets; reduced-motion support; disabled and error states name their reason. Initial theme follows system and persists. Tabular numbers only for real dates/progress.

## Surfaces
Directory: developer knows where to start and can find a provider or research an unfamiliar one.
Guide: next action, evidence, effort, waits and human boundaries are findable.
Research: inputs and observed activity stay visible; no animated fake steps or percentages.

## Limits
No illustrative metrics, decorative charts, provider logos from untrusted remote URLs, or fabricated setup activity.
